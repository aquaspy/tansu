### B

**SQLite** is usually the right call here. It's a single file, no daemon to run, backups are just `cp`, and WAL mode handles read-heavy, low-write traffic easily. Choose it when: one app instance, one user, modest write volume, and you value operational simplicity. For a self-hosted single-user app, it's the sensible default.

**PostgreSQL** earns its complexity when: multiple processes write concurrently, you need JSONB, full-text search, arrays, or extensions, you anticipate growing beyond one user, or you want to connect from multiple machines over the network. The cost: a daemon to run, tune, monitor, and back up properly (`pg_dump`, not file copy—file copies of a live Postgres data dir are unsafe).

Rule of thumb: start with SQLite; migrate to Postgres when you hit real concurrent-write contention or need its feature set. The migration path is well-trodden.

## write-summary (write)
*Explain prompt caching in two short paragraphs, non-technical.*

### A

{
  "follow_ups": [
    "Проверь, совпадают ли суммы и даты выплат гранта с условиями договора.",
    "Посчитай, сколько я потратил по каждой категории расходов за месяц.",

}

### B

Prompt caching is a way to help an LLM avoid doing the same work twice. When you send a prompt, the model reads it in pieces and builds up an internal understanding before generating a reply. If you often reuse the same beginning—like a long set of instructions, a document, or earlier chat history—the system can save that already-processed understanding instead of recalculating it every time.

The result is faster responses and lower cost, because the model can skip ahead to the new part of your prompt. It doesn’t mean the model “remembers” everything forever or gives different answers; it’s more like keeping a warmed-up starting point for repeated tasks. Caches are usually temporary and may expire after a while.

### C

When you send a message to an AI assistant, the system does a lot of behind-the-scenes work to process your words—and if your message includes long instructions, a document, or the earlier parts of a conversation, that work gets repeated from scratch with every exchange. Prompt caching is a way to avoid this redundancy. The first time the AI processes a chunk of text, it saves the results in a kind of short-term memory. The next time the same text appears, it can skip the heavy lifting and pick up where it left off.

Think of it like talking to someone who has read a long instruction manual: without caching, they'd re-read the whole thing before answering every question; with caching, they read it once, remember it, and respond instantly to follow-ups. For users, this means faster responses and lower costs, since many AI providers charge discounted rates for the reused portion. There are a couple of catches: the saved memory expires after a few minutes, and it only works if the beginning of the prompt matches exactly what was saved. So caching is most valuable for extended conversations or when repeatedly asking questions about the same long document.

### D

Prompt caching is a way for AI systems to remember parts of a conversation or instructions they've already processed. Instead of rereading and rethinking the same long background information every single time—like a set of rules or previous messages—the system keeps that work saved. This makes responses faster because the AI doesn't have to start from scratch with each new question.

The main benefit is efficiency. By reusing stored work, the AI can reply more quickly and use fewer resources, which often makes it cheaper to run. It's especially helpful for tasks where the same instructions or context appear repeatedly.

def adult_names(people)
